# GS2-09.9 `/5` activation source window

Owner: FS.GG.Coordination. This work keeps the existing `GS2-09.9 — Qualify callable ordinary v2 execution` roadmap identity and the owner amendment in `evidence/github-substrate-v2/roadmap-amendments/GS2-09.9.json`. It creates no second roadmap unit or acceptance receipt.

## S1: internal executable boundary

`eng/callable_isolated_v2_runtime/` is the first executable source window. An internal composer supplies immutable source, artifact, workflow, target, request, run, approval, issuer, and journal coordinates; a protected active-key reader; separate native read/write and token adapters; and a durable journal path. The signed canonical Ed25519 grant binds every coordinate and expires within 30 minutes. Grant rejection precedes token lookup, attempt reservation, and POST.

The retained `/5` operator parses complete native GET pages, proves absent prestate, sends at most one POST, and classifies two matching complete poststate readings. S1 wraps its `run_pull_once` and `classify_pull_after_one_attempt` boundary. The bound request carries the exact canonical bytes from the plan, without a newline, and the writer receives those bytes. SQLite compares the expected parent generation and head against its stored parent in the same immediate transaction that commits `attempt_may_have_started` with `synchronous=FULL`. A separate connection rereads the committed row. Competing operations on one parent can win one reservation. The trusted key and expiry are checked before token lookup and again after token acquisition, immediately before POST. Each check samples the trusted clock after key and cryptographic work. The exact provider response or loss marker is persisted for recovery; a pending outcome after a crash cannot become success. Recovery rereads with that response and never resends. Incomplete or contradictory readback is `Unknown`.

## S2: protected adapter source

`adapters.py` composes the internal runtime from distinct protected configuration, grant, issuer/key, parent, clock, read, token and write roles. Its fixed GitHub API origin and immutable binding reject caller-selected endpoints, keys and ports. The adapter verifies the signed grant before establishing a stored parent, checks issuer and key custody, and rechecks grant, issuer, key, token and write-scope expiry at the send edge. It preserves a received provider refusal even if a later observer fails. A separate read-only recovery composition requires the exact stored parent.

These are source contracts with an injected `ProtectedAuthority`; no production authority implementation, credential or key store, protected parent provider or external HTTPS transport is installed by this window. The local SQLite bootstrap is not protected journal authority.

## S3: process qualification and remaining activation

Separate-interpreter tests interrupt execution before and after a possible POST, race eight processes on one parent, inspect the durable fence from a fresh process and count token and POST effects. They prove one-attempt recovery for the internal source runtime; the protected adapter tests exercise delayed scope and key readers, expiry, revocation and known provider refusal. This window has no installed production CLI route or accepted live `/5` receipt.

The next activation window must supply and qualify the actual protected authority, identities, runner, journal CAS/readback and exact installed artifact against the external provider. Historical `/4` acceptance and the existing `/5` contract, proposal and native operator retain their identities. Do not change activation state from source or synthetic process evidence.

## S4/S5 candidate artifact interface

The next two source lanes share one new artifact identity, `fsgg.gs2-09-9-v5-runtime-candidate/1`. The builder emits exactly `callable-isolated-v2-runtime.pyz` and a sidecar `callable-isolated-v2-runtime-manifest.json`; the sidecar is outside the archive so its `archiveSha256` cannot hash itself. The manifest is canonical JSON with `schema`, `sourceRevision` (40 lowercase hex), `sourceTree` (40 lowercase hex), `builderSha256`, `retainedOperatorSha256`, `archiveSha256`, `runtimeRequirements`, and a path-sorted `members` array of `{path, sha256, size}`. Each digest is lowercase SHA-256 hex; source and tree are the exact checked-out commit and Git tree. No timestamp, runner path or credential enters the artifact or manifest.

The manifest bytes are UTF-8 JSON with sorted keys, compact separators and one trailing LF. `runtimeRequirements` is exactly `{"pythonMin":"3.11","sqlite":true,"opensslEd25519Pkeyutl":true}`. The archive member roster is fixed: `__main__.py`, the five `callable_isolated_v2_runtime/` modules (`__init__.py`, `contracts.py`, `grant.py`, `coordinator.py`, `adapters.py`), and `callable_isolated_v2_retained_operator.py` with bytes identical to `eng/callable-cli-isolated-operation-v2.py`. No test, cache, configuration, token or key is a member. `python3 callable-isolated-v2-runtime.pyz --check-imports` may perform only read-only import and identity checks; every other direct CLI invocation refuses. Effect and read-only recovery remain the internal `execute_installed(authority)` and `recover_installed(authority)` API behind a separately installed protected host, with no endpoint, credential or key-selection flags.

S4 owns the deterministic builder, relocated runtime loader and sidecar verifier. The builder command is `python3 eng/build_callable_isolated_v2_runtime.py --output-directory <dir>` and emits the two fixed filenames there. The verifier command is `python3 eng/verify_callable_isolated_v2_runtime_artifact.py --archive <path> --manifest <path>`. S5 owns a distinct source-only candidate workflow, workflow validator and retained Actions witness. Its witness binds repository, exact workflow bytes, source revision, successful run and attempt, artifact ID and downloaded archive/manifest bytes to the frozen interface. The workflow grants no effect credential or approval. Existing closed-scaffold builders, witnesses and historical `/4` files stay byte-identical. Artifact assembly and a successful hosted candidate do not establish protected authority, journal CAS, runner installation or native `/5` acceptance.

## S6: native candidate observation and protected host source

Two disjoint source lanes prepare the bridge from a retained candidate to an installed runtime. The native candidate read adapter consumes independently authenticated, read-only Actions observations and downloaded bytes. It must derive repository, source revision and tree, workflow identity, successful first run attempt, artifact identity, complete membership and digest from those observations before calling the S5 witness. An absent native field remains unavailable; a caller-selected value cannot be copied into an observed field. The S5 candidate schema and the two artifact filenames remain fixed. This lane reads no execution token and performs no provider write.

The protected host loader separately verifies the actual archive and sidecar bytes against a host-provisioned expected source, tree, artifact and workflow identity before importing the seven-member runtime. The candidate witness identifies bytes but grants no authority. The host and verifier are outside the archive and require their own protected installation and source attestation. A missing authority refuses before journal, token or provider effects. The candidate producer run is distinct from the later execution run.

## S7: protected journal capability

The installed composer must acquire a protected journal capability with reservation compare-and-swap, independently committed replay and durable outcome persistence. The local SQLite journal remains a qualification backend; it cannot silently stand in for protected journal authority. Concurrent attempts on one parent admit at most one reservation. Rejected or uncertain reservation and missing or mismatched replay permit zero POSTs. A lost response or interruption keeps the attempt fence, and recovery never obtains an execution token or sends another POST. Explicit acknowledgement and unknown outcomes are separate. The source seam and synthetic failure tests do not prove a production backend or its custody.

S6 native reads, S6 host loading and S7 journal source may be prepared in parallel because their file touch sets are disjoint. Integration owns shared interface decisions, the exact seven-member artifact roster, the candidate workflow and the final source qualification. A hosted candidate must be rebuilt from the final integrated source revision; an earlier candidate cannot qualify later runtime bytes.

## Protected activation boundary

Source qualification is followed by an actual successful hosted candidate, protected installation and readback of the archive, host, verifier, interpreter and runner, then real configuration, issuer/key custody, scoped credentials, protected journal backend and a distinct reviewer. Only fresh approval and grant evidence bound to the chosen source, artifact, target and execution attempt can precede a bounded native operation. Provider response, recovery, independent readback and cleanup remain required for `/5` acceptance. Any missing protected dependency leaves the roadmap prepared, not authorized.

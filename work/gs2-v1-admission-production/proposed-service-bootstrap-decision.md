## Why a new decision is necessary

The accepted [genesis handoff](main-host-handoff.md) was a one-attempt operation for the first v1 admission journal ref. [ADR-0087](https://github.com/FS-GG/.github/blob/main/docs/adr/0087-single-owner-v1-admission-genesis-approval.md) confines its owner environment and approval exception to that genesis. The accepted [GS2-08.4 receipt](../../evidence/github-substrate-v2/accepted/GS2-08.4.json) establishes a common source fence, not an installation exception. `.github` PR [#3690](https://github.com/FS-GG/.github/pull/3690) merged natively while common production v1 admission remained unavailable; retain that event as an **unadmitted observation**, not precedent or authority.

The new Actions service and Main issuer must be installed before routine `.github` delivery can use ordinary admission. No accepted standing bootstrap route was found in the genesis or GS2-08.4 records. This packet proposes a separately governed, single-use protected installation. It does not assume that an ordinary native PR merge is exempt from the existing fence.

## Proposed protected installation scope

1. Prepare one staged `.github` integration PR containing the exact independently reviewed #3694 design, #3695 routine client safety and inactive service workflow bytes, including any reviewed stacked predecessors. Recompute its final tree, path/blob manifest and exact-head checks after staging. The separate one-time decision may approve that exact candidate without claiming its constituent draft PRs already merged; no individual draft is itself installation authority.
2. Before final source-packet approval, a **separately authorized** administrator installs and independently reads back a provider-enforced exclusive base-writer rule and its complete bypass census. That administration effect needs its own exact protected decision, bounded scope, expiry and readback receipt; this packet cannot bootstrap it implicitly. If no independent administrative authorization route exists, stop. Recollect the source base SHA, effective rule/bypass state, epoch and admission heads **after** that administration effect, and rebuild/review the source packet if any value moved.
3. The accountable owner then approves only the filled post-administration packet and one protected `.github` source-update attempt for the exact staged PR head and freshly pinned base. This decision does not install a provider rule, Main policy, runtime issuer artifact or key. It cannot merge another PR, dispatch the service, mint a runtime token, append a journal event, or perform an ordinary provider effect. A separately qualified Main-local one-shot installer may use the sole allowed App credential for this exact source update, under this decision only; no credential crosses to Actions. The installer rechecks its own identity, current base SHA, PR head, exact path/digest set, required checks, review state and packet expiry immediately before that update. GitHub's native PR merge accepts an expected PR head but has no expected base SHA; the exclusive writer rule must make the base stable during the update. If exclusivity cannot be proven, the update refuses.
4. Treat the source-update response as unknown until a separate native read proves exact resulting main commit/tree, staged PR merge result, workflow bytes and rule state. A lost response is not permission to retry. Main policy and issuer artifact installation require separate protected Main custody and a one-shot consume decision after source readback.
5. Keep the service inactive and the dedicated ordinary App key unavailable while a protected read-only service probe verifies actual signed GitHub `sub`, `workflow_sha`, environment node ID and check-run ID semantics, native run/job/workflow/environment joins, environment approval requirements, and two-read completeness. The Actions job holds no App key; only Main-local issuer and executor processes may receive a scoped credential. A public unknown/verified receipt may return to Actions; no bearer token may cross to it.
6. A later, separate exact qualification decision may enable ordinary admission and then the `.github` routine-delivery client. Native merge remains disabled until provider-specific Applied/readback and StronglyAbsent exclusion, every-attempt authority/fence, base-writer exclusivity and protected caller composition are accepted. This installation decision cannot itself lift the production fence.

## Refusal and recovery

Missing, changed, partial, stale or contradictory packet facts; moved authority/epoch/claim/target; changed rules or bypasses; expired approval; unsuccessful hosted gate; unproven exclusive base control; absent native approval; or indeterminate source update stops the attempt. Before a provider effect, abandon the packet. After an uncertain effect, perform independent native readback and reconcile the exact original request; do not repeat it from a timeout or an unmerged PR view. If source installed but probe or Main policy fails, keep the service and key path disabled and the common v1 effect fence closed. Preserve the native history and issue a new governed repair decision rather than restoring older authority or treating rollback as erasure.

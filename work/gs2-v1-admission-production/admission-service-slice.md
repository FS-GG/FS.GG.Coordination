# Dormant v1 admission service slice

The existing `Protocol.md` is the source of truth. In `OperatingV1`, one canonical protected Operation journal admits an inventoried operation by expected-parent CAS. An operation handle is usable only after exact durable readback; a lost response is not a fresh dispatch permit. A missing genesis journal is a failed read, not an empty registry to initialize.

`V1AdmissionService.admit` composes the existing typed verifier, replay, admission decision, deterministic command identity, exact append proposal, and append-and-reconcile boundary. The command identity is stable for an operation id and generation, so a restart does not manufacture a different journal event. The service does not create the genesis ref, issue credentials, inventory incumbents, call a provider, or enable the ordinary CLI. It returns the durable handle only when the confirmed registry still contains the exact requested binding. An absent/malformed journal or unavailable authority is indeterminate; a parent conflict is reported with the freshly read head for a caller to replan explicitly.

The next source slices require a production `RegistryJournalPort`: raw Git history read and exact object verification, a scoped writer capable of expected-parent receive-pack CAS, and provider reconciliation that preserves response-unknown as unknown. Those ports must be tested against independent fake providers before the ordinary production fence can be removed. The live admission journal remains absent, and the current public Main trust-anchor copy does not match the live OperatingV1 anchor digest (`0a9f84f72ca10c01b5acc386a32ce6920fea15231f90f65a8f17df9e87d9a779`), so no protected dispatch or install is permitted with that copy.

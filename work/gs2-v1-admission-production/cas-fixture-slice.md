# Source-only exact-parent CAS fixture

`V1AdmissionJournalCasPlan.encode` serializes an opaque typed append proposal into a public-only, fixed-repository CAS envelope. `eng/github-v1-admission-journal-cas.py` independently validates that complete plan (fixed repository and admission ref, parent and proposed commit, two exact blobs, canonical two-entry tree, and deterministic one-parent commit) before any write boundary. Its fixture path requires an absolute local bare-Git directory. It fetches the current parent, stages only verified object bytes, and pushes under `--force-with-lease=<canonical-ref>:<expected-parent>`. A preflight parent move is a conflict; a failed or lost push response remains unknown until independent journal readback. A typed serialization test and four local bare-Git tests cover the envelope, successful append, stale parent, concurrent sibling update, lost success, and tampering. Q6 runs these tests.

This is deliberately **not** a production writer or a deployment entry point. It has no ordinary-App credential channel and refuses a network remote. The Main custody helper's current JWT issuance is bound to an approved *genesis* workflow run; it is not a standing credential issuer for subsequent admissions. The production slice must explicitly review a scoped, secret-safe credential path and Git receive-pack transport, wire it to the typed `RegistryJournalPort`, and independently reread the exact installed journal after every outcome. The ordinary CLI production fence stays in place. The wrong public trust anchor still blocks protected genesis installation; this fixture does not relax that gate.

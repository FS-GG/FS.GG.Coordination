# Closed complete target prestate reader

Status: source and fake native GET controls, 2026-09-25, stacked on [#600](https://github.com/FS-GG/FS.GG.Coordination/pull/600). The [adapter](../../eng/callable_isolated_v2_target_prestate_read_adapter.py) derives a candidate prestate digest from the provisional native v2 reader in [#582](https://github.com/FS-GG/FS.GG.Coordination/pull/582). It has no HTTP client, token, journal, grant, mutation or dispatch entry. Its wrapper exposes only GET with no body. The #563 inspect-only workflow remains disabled.

For one selected repository, installation, source/base refs and SHAs, the adapter asks the native reader for two complete pull censuses. Each census reads repository identity, both refs, all open PR pages and details, a terminal empty page, then repository and refs again. The adapter requires exact repository ID and ref SHAs, no PR with the operation's deterministic marker, identical complete transcript SHA-256 in both censuses, and at least the 16 expected GETs. It derives prestateSha256 from the selected target, protected run ID/attempt and transcript digest, then compares it to the selected digest. This is absence of the selected operation marker at two observed instants; a source-only reader cannot prove that the target never changed between them or that a protected provider credential performed the GETs.

The read port claims only metadata:read, contents:read and pull_requests:read on the one selected repository; that scope is snapshotted and checked before and after both censuses. A red-before control showed that returning one mutable scope dictionary twice and changing its credential at the final read hid drift; the adapter now refuses that alias. A distinct injected protected witness must bind the same run/attempt, repository ID/node/installation, refs/SHAs, prestate and transcript digests and fresh expiry. There is no witness implementation. The selected repository's node ID is cross-checked by the separate [#592 target reader](target-scope-read-adapter.md); this native reader checks its numeric ID and full name. The [#600 credential adapter](app-credential-record-adapter.md) still needs a protected effective-scope observation that consumes this independently witnessed prestate, not an echo of the selected digest.

The returned observation preserves the witness principal, credential and observation/expiry timestamps alongside its record ID. The downstream [effective-scope join](effective-scope-prestate-join.md) checks these identities against both reader roles. These fields are claims of an injected witness port until an independent protected event source verifies them.

The witness's repository and installation IDs require positive integer types before comparison. Red-before fake controls showed that Python equality otherwise accepted `true` as selected numeric ID `1` in both fields, even when the selected digest and native read transcript matched.

The [fake negatives](../../eng/tests/callable-isolated-v2-target-prestate-read/test_target_prestate_read_adapter.py) cover foreign repository/ref, changed second snapshot, a matching PR marker, missing terminal page, wrong selected digest, broad reader scope, foreign/stale witness, scope drift and sanitized provider exceptions. The matching fake closes file, token environment, socket and SQLite access. These controls exercise no protected target or one-POST window.

The actual effect artifact/workflow, independent review audit join, execution token capability, durable CAS, one-use grant, installed no-grant refusal and native poststate readback remain missing.

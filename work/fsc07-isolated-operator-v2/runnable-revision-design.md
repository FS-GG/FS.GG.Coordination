# Proposed runnable isolated v2 source revision

Status: source design for review, 2026-09-25. This file proposes the next **separate** native v2 artifact revision. It does not build an archive, enable a workflow, install a token, create a journal marker or authorize the [#550 one-POST window](https://github.com/FS-GG/FS.GG.Coordination/pull/550). The current [closed scaffold](closed-effect-scaffold.md) remains byte pinned and exits 78. Its native operator is external to the archive; it cannot be declared runnable by changing a workflow input.

## Source graph to review

The proposed executable is a new Python zipapp invoked as `python3 -I -S <selected archive> execute-native-pull`. It would have its own builder, manifest schema, archive name and protected producer workflow. It would not replace the existing closed builder, archive, [entry](../../eng/callable_isolated_v2_effect_entry.py) or disabled [execution proposal](../../.github/workflows/callable-isolated-v2-execute.yml). The installed `FS.GG.Coordination.Cli` 0.1.1 `delivery advance` command and historical v1 operator remain separate; neither is a compatible PR-creation entry.

A new archive that includes the native operator must explicitly map its archive member to the exact source path and hash. Its modules must be side-effect free on import: direct import of a native or provider member must not discover a token or send a request without the sealed grant, protected CAS and exact selected operation. This is a new review obligation because the present closed archive deliberately omits native bytes after an alternate-entry test found they could be imported or extracted.

The [source cross-check](../../eng/tests/callable-isolated-v2-native-request-crosscheck/test_native_request_crosscheck.py) compares the existing sealed plan adapter with the provisional native operator's pure `pull_request_body`: exact title, body marker, canonical request SHA-256, POST path and one-write ceiling agree. Changing each selected repository/ref/SHA coordinate changes that request, and resealing a foreign native request still fails the plan join. This is offline source consistency only. A future installed adapter must use the same selected request bytes for the grant, journal intent and sole provider POST; the operation ID is bound separately by those records and is not encoded in the PR body.

## Ordered source gates

1. **Diffable proposal:** review the file graph, versioned grant/evidence and journal interfaces, exact method/path/body rules and independent role custody. The provisional [v5 authority amendment](https://github.com/FS-GG/FS.GG.Coordination/blob/19323acc60f6f1314b9c92030c203bf2789e21ad/work/gs2-09-9-isolated-operator-rotation/authority-amendment.md) is `prepared-not-authorized`; historical `/4` credentials and grants do not transfer. This document is only that design input.
2. **Closed runnable candidate:** in a new source revision, build exact archive bytes but retain an installed no-grant refusal. Source tests must cover absent/malformed/replayed grant; wrong source/workflow/artifact/image/interpreter; swapped reviewer/issuer; foreign target or broadened App scope; alternate entry; secret-sentinel output; and zero token, journal, CAS, POST, PUT and cleanup counters on pre-intent failures. Fake-port success remains non-authoritative.
3. **Protected release selection:** only a distinct owner and reviewer may select an integrated Coordination commit/tree, protected `.github` workflow, producer run/artifact, immutable runner/runtime and approved manifest. Independent observers then read back installed path/object/bytes and the no-grant counters. Neither a source merge nor installation alone issues effect authority.
4. **Separate native authorization:** after separately granted setup, target/App scope and complete prestate, the protected journal owner commits and independently reads back one intent. A distinct reviewer approves the exact execution run/attempt and an issuer creates one byte-bound short-lived grant. The installed entry rereads all facts before the one POST. Lost CAS or POST acknowledgment spends the attempt; complete native readback or Unknown follows, without another write.

The [admission matrix](native-effect-admission-matrix.md) lists the missing immutable coordinates and future negative controls. The immediate blocker for a **protected runnable installation or effect** is the absent reviewed integrated source/workflow selection, protected observer identities and journal/grant custody. The source owner can review this graph now; any implementation must arrive as a separate source revision with new manifest pins and red-before tests. Both workflows remain disabled; #545 disputed receipt, #550 native gate, typed gate/index, Authority boundary and cutover remain held.

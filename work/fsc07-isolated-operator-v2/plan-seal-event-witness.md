# Closed plan-seal event witness

Status: source-only fake-port proposal, stacked on [#738](https://github.com/FS-GG/FS.GG.Coordination/pull/738). The [witness](../../eng/callable_isolated_v2_plan_seal_event_witness.py) adds an immutable-event selection check outside the closed installed archive. It does not read a protected event store, issue a grant, write a journal or dispatch a provider request.

The existing version 1 [plan reader](operation-plan-read-adapter.md) verifies a canonical request and a separate seal, but its seal record has no immutable event ID. This witness accepts that same `VerifiedRequest` and a selected event ID and SHA-256. It asks an injected, distinct read-only event port for the event bytes once, requires canonical duplicate-free JSON and an exact SHA-256 match, and binds the event to the selected candidate, source tree, workflow revision, run and attempt, review event, target repository ID, plan record and digest, operation ID, request digest, and seal producer identity. It rejects an incomplete or foreign event, stale or expired event, changed selection, broad reader scope, and scope drift. Its frozen result always has `authorized=false`, `can_dispatch=false`, and `live_effects=0`.

The selected event digest and identities are caller-supplied in these tests. Matching fake objects prove only local consistency. A protected owner still has to identify an append-only event backend, independently select and authenticate the event ID and digest, attest the producer and reader principals and credentials, preserve exact event bytes, and prove review time and revocation from a protected source. An event ID alone does not provide one-use replay prevention; durable CAS and a one-use grant remain separate protected steps. The witness is not part of a runnable revision or installed effect artifact.

The [negative controls](../../eng/tests/callable-isolated-v2-plan-seal-event-witness/test_plan_seal_event_witness.py) first failed because this witness module did not exist. They now cover independently recomputed digests for changed event fields, wrong selected fields and digest, duplicate or noncanonical bytes, stale events, reader identity and scope, mutable selection/scope, sanitized exceptions, and zero file, token, socket or SQLite access. The #563 inspect-only and effect workflows remain disabled. The [#550](https://github.com/FS-GG/FS.GG.Coordination/pull/550) protected native one-attempt gate and [#545](https://github.com/FS-GG/FS.GG.Coordination/pull/545) receipt dispute remain held; no protected effect, receipt, gate/index, Authority write or cutover follows from these controls.

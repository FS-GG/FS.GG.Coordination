# Closed effect scaffold Git-tree source witness

Status: source-only, non-authorizing. The [closed effect release preflight](effect-release-preflight.md) verifies archive and manifest bytes but its injected source claim alone does not prove that the source files belong to the selected Coordination commit. This witness closes that source-consistency gap for a future protected read-only implementation; it does not select or approve a commit.

`eng/callable_isolated_v2_effect_git_tree_witness.py` accepts a closed preflight result, its exact archive/workflow/manifest/builder/native input bytes, a selected repository ID and separate source-reader custody claim, an injected Git object reader, and a **different** repository-identity reader. The identity reader must return the exact selected repository ID and event ID with `objectFormat:"sha1"`, fresh event time, and its own read-only principal/credential. The two reader scopes and the selected source-reader claim must be pairwise distinct. The witness then reruns the exact scaffold byte verifier, extracts the three archive member source files, and requires all seven source paths to match the selected Git commit and tree. It recomputes each Git SHA-1 object ID, checks the commit's tree line, walks exact tree entries, requires regular `100644` source files, and compares complete blob bytes. Both scopes must remain exact, unexpired and unchanged before/after. Output remains `authorized=false`, `can_dispatch=false`, `live_effects=0`.

Fake controls first failed because the module did not exist. A subsequent red run failed because it could not accept an independent repository-identity reader. They now cover wrong commit/tree, changed builder bytes, independently changed Git blob bytes, a coherent Git tree containing a symlink-mode workflow path, foreign object format/repository/event, shared reader credential, broad or drifting identity scope, stale identity and missing objects. A later red-before control showed that a Git port returning the same scope dictionary twice could change its credential during object reads and still pass the before/after comparison. The validated scope is now deep-copied before comparison. Another red-before control showed that the identity callback could replace a foreign archive in the caller-supplied byte dictionary before the witness checked it; the source bytes are now snapshotted before any port call. The matching fake denies file, environment-token, socket and SQLite access during qualification.

The source contract explicitly refuses a non-SHA-1 format, but a protected owner must establish and authenticate the identity reader, event immutability, actual repository object format, Git-object reader and selected repository ID outside these fake port claims. The witness cannot prove that the preflight result came from a protected producer, that the selected source reader is real, that a producer run used this tree, or that an artifact was downloaded from that run. The [protected owner packet](effect-release-owner-evidence.md) still requires independent producer, approval, runner and audit custody. Both workflows remain disabled; #545's disputed receipt and the [#550 native one-attempt gate](https://github.com/FS-GG/FS.GG.Coordination/pull/550) remain held. No protected install, credential, grant, journal/CAS, provider POST, Authority write or cutover follows from this result.

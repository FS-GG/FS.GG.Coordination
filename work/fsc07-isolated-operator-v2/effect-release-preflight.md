# Closed effect scaffold source and approval preflight

Status: source-only fake-port contract, 2026-09-25, stacked on [#614](https://github.com/FS-GG/FS.GG.Coordination/pull/614). The [preflight](../../eng/callable_isolated_v2_effect_release_preflight.py) joins an injected integrated-source/artifact observation with a separate injected immutable manifest-approval observation. It calls the [exact-byte verifier](../../eng/verify_callable_isolated_v2_effect_scaffold.py) on observed archive, workflow, manifest, builder and external native source bytes. It never reads a token, grants authority, opens a journal, contacts GitHub or dispatches an effect. Every successful result has `authorized:false`, `can_dispatch:false`, `live_effects:0`.

The caller selects one Coordination commit and tree, source record ID, producer run ID/attempt/actor, artifact ID, reviewer actor and approval event ID. The source record must carry that exact selected ID, repository and coordinates, archive and manifest digests and bytes, a fresh observation and its source-reader principal/credential. The separate version 2 approval observation must bind the same source record ID, repository and coordinates, the manifest digest, a different reviewer from the producer, fresh review time and expiry, and a distinct approval-reader principal/credential. The closed version 2 preflight result carries the source record ID. Each read-only scope claim is checked before and after the join. Missing, broad, changed or stale claims refuse. The scopes are abstract port claims, not an authenticated GitHub App grant.

The [fake controls](../../eng/tests/callable-isolated-v2-effect-release-preflight/test_effect_release_preflight.py) failed red before the preflight module existed. They now cover wrong commit/tree/run attempt/producer/reviewer, self-review, stale source or approval, changed archive/builder bytes, shared reader credential, broad scope, scope drift and sanitized read exceptions. A red-before control showed that swapping the source record to another positive ID passed; source selection and both approval joins now refuse that substitution. Earlier red-before controls showed that either source or approval reader could return the same mutable scope dictionary twice, change its credential at the final read, and still pass the comparison. Validated scopes are deep-copied. Another red-before control showed the later approval port could restore foreign archive bytes in the earlier source dictionary before verification; the source result is now deep-copied immediately after its read. The matching fake closes file, token-environment, socket and SQLite access during qualification. The underlying [scaffold controls](../../eng/tests/callable-isolated-v2-closed-effect-scaffold/test_closed_effect_scaffold.py) continue to check clean local no-grant refusal and exact archive/workflow bytes.

A protected implementation must independently fetch the commit and tree relationship, repository file bytes, producer run and artifact object, review event and active reviewer identity from separately authenticated sources. The [reviewer and approval witness](effect-approval-identity.md) adds a fake-port exact-head event/identity join but does not supply those sources. The event must be durable, immutable and externally approved; its digest cannot be chosen by the candidate. This draft supplies none of those transports, credentials or records. It also has no protected runner installation, image/interpreter closure, execution grant, target App scope or CAS. The [owner qualification packet](protected-owner-qualification.md) keeps inspect-only release selection separate from the later execution artifact and one-POST authorization. Both proposed workflows remain disabled; #545 disputed receipt, #550 native gate, typed gate/index, Authority and cutover remain held.

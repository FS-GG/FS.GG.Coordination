# Closed v5 journal intent readback

Status: source-only fake-port contract, stacked on [#741](https://github.com/FS-GG/FS.GG.Coordination/pull/741). The [v5 port proposal](v5-closed-port-proposal.md) names a journal writer and separate replay reader but has no checked join between a writer acknowledgment and committed intent. The [new readback](../../eng/callable_isolated_v2_journal_intent_readback.py) supplies that narrow comparison outside the closed installed archive. It has no CAS writer, token reader, grant issuer or provider transport.

The caller supplies a verified request from the same sealed plan read, selected journal repository/ref/path, operation/grant/target digests, prior and committed generation/head, distinct writer and reader identities, a purported CAS acknowledgment, and an injected replay reader. The source check requires the acknowledgment and independent readback to match every `JournalRecord` field, including `attempt_may_have_started=true`, exact request SHA-256, and a one-generation advance. The replay reader claims only `read-intent` on the selected path; its scope must remain stable across the read. An absent or uncertain CAS acknowledgment refuses before replay access. A matching fake record returns `consistent-but-unadmitted`, `authorized=false`, `can_dispatch=false`, and `live_effects=0`.

These inputs do not authenticate a CAS outcome or prove that a protected write occurred. A caller can fabricate all of them. The protected owner must select the immutable backend and generation, attest the actual writer acknowledgment, independently authenticate a fresh-process replay reader and exact committed bytes, and prove atomicity and no prior attempt before any execution decision. A lost CAS acknowledgment spends the attempt and permits no POST. This source check cannot issue a grant or reopen an ambiguous attempt.

The [negative controls](../../eng/tests/callable-isolated-v2-journal-intent-readback/test_journal_intent_readback.py) failed to import before the module existed. They now mutate each writer and replay field independently, backend/scope/role/generation, unknown CAS outcomes, mutable selection and scope, and reader exceptions. They assert zero token, file, socket and SQLite access. The result is a consistency proposal only. Both effect workflows and #563 inspect-only remain disabled; [#550](https://github.com/FS-GG/FS.GG.Coordination/pull/550) native effect, [#545](https://github.com/FS-GG/FS.GG.Coordination/pull/545) disputed receipt, protected merge, Authority write and cutover remain held.

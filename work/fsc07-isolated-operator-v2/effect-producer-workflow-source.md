# Producer workflow source binding for the closed effect scaffold

Status: source-only, non-authorizing fake-port contract. The [producer artifact witness](effect-producer-artifact-witness.md) previously accepted a selected workflow hash repeated in a fake run. A red-before test showed it could pass with no workflow source object. It now requires a closed workflow-source result for the same Coordination revision/tree, repository-identity event, workflow path and SHA-256 before it reads a producer run.

`eng/callable_isolated_v2_effect_producer_workflow_source.py` takes the [Git-tree witness](effect-git-tree-witness.md), an exact selected workflow SHA-256, and an injected Git object reader with a read-only scope distinct from the source reader. It re-reads the selected commit and tree, follows `.github/workflows/callable-isolated-v2-effect-release.yml` to a regular-file Git blob, verifies Git object IDs and complete workflow bytes, and checks the selected SHA-256. The scope is checked before and after. The result carries the exact blob ID and remains `authorized=false`, `can_dispatch=false`, `live_effects=0`. Fake negatives cover absent/foreign path, symlink mode, wrong tree or bytes, foreign selected hash and reader/scope drift.

A disabled [producer workflow candidate](effect-producer-workflow-candidate.md) is added in this stacked draft. The positive adapter test still uses a synthetic Git tree; the protected integrated commit, selected workflow blob and authenticated Git reader have not been observed. A protected owner must independently review its exact bytes/hash and source membership. This contract validates membership and byte consistency, not workflow safety or production readiness. Both proposed workflows remain disabled. #545's disputed receipt and the [#550 native one-attempt gate](https://github.com/FS-GG/FS.GG.Coordination/pull/550) remain held; no protected install, credential, grant, journal/CAS, provider POST, merge, Authority write or cutover follows.

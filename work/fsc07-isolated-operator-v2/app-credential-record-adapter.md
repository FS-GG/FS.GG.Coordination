# Closed execution App credential metadata adapter

Status: source and fake metadata ports only, 2026-09-25, stacked on [#598](https://github.com/FS-GG/FS.GG.Coordination/pull/598). The [adapter](../../eng/callable_isolated_v2_app_credential_record_adapter.py) implements the attestation interface consumed by the [selected-target reader](target-scope-read-adapter.md). It never handles a token, calls GitHub, mints a credential, opens a journal or dispatches an effect. The #563 inspect-only workflow remains disabled.

GitHub [documents](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app) that an installation token defaults to every installed repository and every granted App permission unless the mint request explicitly narrows both. Its response includes a token alongside expiry, selected repositories and permissions. This adapter accepts only a separately stored **redacted metadata record**, with no token field, for a mint request that names one repository ID and exactly metadata:read, contents:read and pull_requests:write. It checks the matching redacted response object, selected repository ID/node/name/API URL, target and four target-read response hashes, issue/expiry times, source/base refs and SHAs, and the exact selected prestate digest. Extra fields, broad scope, default-all selection, changed target and noncanonical or duplicate JSON refuse.

A second injected effective-scope witness must independently bind the redacted mint record SHA-256 and the same credential ID, App ID, installation ID, one-repository set, permissions, target/read hashes, prestate digest and expiry. The metadata reader and witness must have distinct protected principals and credentials. These source checks cannot prove that the witness actually observed the minted token's effective permissions or that the prestate digest came from a complete native census. A protected owner must specify the issuer, secret-free metadata extraction, token custody, App installation identity, effective-scope measurement and independent prestate reader. No port implementation is provided here.

The [fake controls](../../eng/tests/callable-isolated-v2-app-credential-record/test_app_credential_record_adapter.py) cover omitted or extra repository and permissions, foreign installation/App, default-all selection, token-bearing record, changed response bytes, stale issue/witness, self-witness, broad reader scope, scope drift and sanitized exceptions. A malformed source ref repeated consistently by every fake record was red before selected-target validation was added. The matching fake patches file, token environment, socket and SQLite access closed. It creates no real credential.

The exact effect artifact/workflow, protected issuer/witness identities, immutable review-event and joint record, complete target prestate, durable CAS, one-use grant, installed no-grant refusal and one-POST native readback remain separate protected admissions. The typed ceiling, #550 one-attempt hold, gate/index, #545 disputed receipt, Authority boundary and cutover remain unchanged.

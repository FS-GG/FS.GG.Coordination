# Closed review audit event and joint-seal adapter

Status: source and fake ports only, 2026-09-25, stacked on [#596](https://github.com/FS-GG/FS.GG.Coordination/pull/596). The [adapter](../../eng/callable_isolated_v2_review_audit_read_adapter.py) implements the audit protocol required by the [review reader](review-read-adapter.md). It has no organization audit-log client, token, store, seal writer, grant, journal or dispatch path. The #563 inspect-only workflow remains disabled.

GitHub [documents](https://docs.github.com/en/organizations/keeping-your-organization-secure/managing-security-settings-for-your-organization/audit-log-events-for-your-organization) a workflows.approve_workflow_job organization audit event with a document ID, actor, repository, workflow run ID and timestamp. The listed event fields do not include the run attempt, environment ID or exact review-history response bytes. The adapter therefore reads one injected raw audit event by its exact document ID and requires the documented action, organization/repository names and numeric IDs, reviewer login/ID, run ID, equal millisecond timestamps and a fresh UTC approval time. It rejects duplicate JSON, malformed fields and changes in the claimed audit read scope.

A separate, injected immutable joint-seal reader must bind the raw audit event SHA-256 and the exact GitHub approval-history response SHA-256 to a positive protected record ID, run attempt, environment ID, reviewer ID, repository/organization IDs and a short expiry. That record ID is what the existing candidate schema calls reviewEventId; it is not GitHub's string audit document ID. The audit reader and joint sealer must have distinct protected principals and credentials. Matching fake dictionaries only establish local consistency: a real protected owner must select the audit access principal, immutable joint-record backend and independent issuer, and demonstrate that the join was recorded at approval time rather than self-asserted later. The actual GitHub audit access permission and identity must be separately verified; the local audit-log:read scope label is an abstract claim.

The [fake negatives](../../eng/tests/callable-isolated-v2-review-audit-read/test_review_audit_read_adapter.py) cover foreign document/action/actor/repository/run, stale or contradictory timestamp, missing or replayed joint mapping, wrong attempt/environment/approval bytes, broad/drifting claimed scope and sanitized exceptions. A boolean run attempt was a red-before false green and now refuses. The positive fake patches file, token environment, socket and SQLite access closed. No audit event, approval, token or protected seal was read.

This work does not make the five candidate observers authoritative. The protected App read identity and effective permissions, released effect artifact/workflow and attempt provenance, full target prestate, execution credential issue record, durable CAS, one-use grant, installed no-grant refusal and native one-POST readback remain absent. #550 native authority, the typed ceiling, gate/index, #545 disputed receipt and cutover remain held.

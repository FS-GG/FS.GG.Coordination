# Read-only candidate observer port before protected v2 execution

Status: source and in-memory controls, 2026-09-25, stacked on draft #585. This code does not fetch GitHub data, install an artifact, issue a grant, open a token or journal, or dispatch a provider request. The inspect-only #563 workflow remains disabled.

The [observer composition](../../eng/callable_isolated_v2_candidate_observers.py) defines five future read-only ports: source release, workflow/run actor, review/membership, selected target/App scope, and operation plan. Each observation must carry its role, distinct principal and credential IDs, record ID, exact candidate payload digest, UTC observation time within 30 minutes, and complete facts. The source port supplies operator/control/archive bytes whose SHA-256 values are recomputed; the workflow port supplies workflow bytes whose hash is recomputed. The candidate now also binds the release producer run ID, artifact ID and actor ID. A red-before fake-observer test showed all three could previously be swapped without changing the candidate.

The composer derives the expected candidate solely from those five observer results and calls the strict #585 candidate verifier. It checks release producer separation from the reviewed run and reviewer, workflow actor/run against review, exact one-repository App selection and narrow permissions, review and credential expiry, and the candidate's source/runtime/target/operation fields. Its only result has `authorized:false`, `can_dispatch:false`, `live_effects:0`; producer and artifact IDs plus an observation digest are evidence identifiers, not execution authority. Distinct in-memory objects and self-declared principal IDs cannot prove real independent custody.

The [independent fake-observer tests](../../eng/tests/callable-isolated-v2-candidate-observers/test_candidate_observers.py) cover changed archive, operator, controls and workflow bytes; source/runtime/workflow/actor/target/operation drift; swapped producer run/artifact/actor; same observer principal, missing/foreign/incomplete evidence; stale review or observation; broad or extra-repository credential; and a secret-bearing observer exception. A matching fake result remains closed while file, token environment, socket and SQLite entry points are patched to fail.

A meaningful protected implementation still needs independently authorized GitHub App read credentials and exact API/readback contracts for protected Coordination source/tree and producer artifact, `.github` workflow/run, environment approval and active membership, target installation/refs/prestate and effective token scope, plus a separately sealed operation plan. Those credentials and API implementations are not selected or available in this draft. The observer's claimed credential ID is not proof of its effective permission or origin; a protected adapter must establish that from the provider and retain immutable response IDs/hashes. A later installed effect artifact must independently verify the grant, durable CAS marker and complete native poststate before a separate reviewer can approve one POST. Current typed ceiling, gate/index, #545 receipt and cutover stay held.

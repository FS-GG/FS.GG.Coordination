Status: source-only fake-port candidate stacked on draft #776. It pins the #764 entry, builder, verifier, manifest and disabled workflow bytes; checks the canonical ZIP manifest; verifies SHA-1 object IDs for the selected commit, nested trees and blobs; and requires each selected path to be a regular Git blob with exact bytes. The repository-format event must say `sha1`. Both readers have separate fake scope from each other and from the prior source, review, artifact and workflow readers. Success remains `authorized=false`, `can_dispatch=false`, `live_effects=0`.

The [tests](../../eng/tests/callable-isolated-v2-v5-git-tree-membership/test_v5_git_tree_membership.py) began red because the v5 witness was absent. Other negatives cover foreign commit/tree/blob bytes, symlink path mode, wrong object format/event and shared reader identity. The qualification call performs no file, token-environment, socket or SQLite access.

All Git objects and identity events in these tests are fake. This does not establish that the protected Coordination repository served the selected commit, that the producer workflow ran at it, or that the installed archive was independently fetched from that run. A protected owner still needs an immutable integrated revision, authenticated Git/provider object and producer readback, independent review event, runner/image/runtime and actual installed refusal.

# Closed effect scaffold installed-refusal readback contract

Status: source-only, non-authorizing. The [protected owner packet](effect-release-owner-evidence.md) has no selected integrated revision, producer artifact, independent approval event or runner. Both proposed workflows remain disabled.

The [release preflight](effect-release-preflight.md) carries the verified archive SHA-256 into its closed result. A red-before control showed that installed no-grant readback could qualify without the separate [immutable reviewer witness](effect-approval-identity.md). `eng/callable_isolated_v2_effect_runner_readback.py` now requires that closed witness and checks its source, producer, manifest, artifact, reviewer and approval coordinates against preflight before reading the runner. It then takes an exact run/attempt, runner actor distinct from the release reviewer, selected audit actor and event, immutable image and attestation digests, interpreter and runtime-closure digests, and an absolute canonical install path. It compares two injected read-only observations:

1. A runner probe with the same source revision/tree, manifest, artifact and archive hash, plus the approved repository ID, repository-identity event ID, source record ID and approval event ID; exact installed archive bytes; the same before/after device, inode, size and hash; no symlink claim; the pinned `python3 -I -S` argv; exit 78; and the exact `no-grant` JSON line with empty stderr. Version 2 of the probe carries command start and completion times.
2. A separately read audit event with those same source and approval coordinates, run, artifact, install path and file object; the exact selected audit actor distinct from the runner, separate observer principal and credential; the same command start/completion interval as the runner probe; and zero token reads, journal reads/writes, CAS writes, provider POSTs and cleanup attempts. A merely positive foreign audit actor refuses even when the event ID and all other fields match.

The runner and audit scopes are checked before and after reading. Red-before controls showed that either reader could return the same mutable scope dictionary twice, change its credential at the final scope read, and still pass the comparison. Validated scopes are deep-copied before comparison. Later red-before controls showed that a probe before claimed approval or a readback after claimed approval expiry could qualify. Another red-before control showed that a probe with no command execution timestamps could qualify using observation time alone. A further red-before control showed that the separate audit could omit that interval entirely and the readback still qualified; version 2 audit now must corroborate the exact start/completion strings. Another red-before control showed that a selected runner actor equal to the release reviewer qualified when the probe and audit agreed; version 6 readback rejects that collision before reading either port. A new red-before control showed the audit callback could replace a foreign earlier probe stdout with the exact refusal line before validation; the probe is now snapshotted immediately after its read. Version 5 readback requires claimed approval ≤ command start ≤ command completion ≤ runner observation ≤ separate audit ≤ readback time, with approval still unexpired. Missing fields, broad scope, foreign identities, stale times, malformed counters, path aliases, changed archive bytes or object identity, and any nonzero effect count refuse. The output remains `authorized=false`, `can_dispatch=false`, `live_effects=0`. Tests use fake ports and deny local file, environment-token, socket and journal access while qualifying.

This source join checks the claimed time order. It cannot authenticate either fake port's timestamps, prove the claims came from independent clocks, prove a runner image or interpreter digest, detect a transient ABA mutation between before/after observations, or prove external counters from a real protected host. The selected audit actor is an input; its identity must come from an independently reviewed protected decision, not the audit event itself. A protected owner must supply immutable source/producer/approval identities, independent reader credentials, a pinned runner image and runtime closure, and an independently observed no-effect probe under a separate installation decision. The closed artifact has no runnable native effect; a future runnable artifact, selected target, credential custody, CAS journal, grant and one-POST authorization remain a distinct [#550 native gate](https://github.com/FS-GG/FS.GG.Coordination/pull/550). #545's disputed receipt, typed gate/index and cutover remain held.

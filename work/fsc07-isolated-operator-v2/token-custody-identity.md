# Closed public token-handle custody proposal

Status: source-only fake-port contract, stacked on [#755](https://github.com/FS-GG/FS.GG.Coordination/pull/755). The [observer](../../eng/callable_isolated_v2_token_custody_identity.py) accepts the public credential metadata result, selected target and native run, and one selected token-vault public-binding event. It reads only canonical token-free event bytes from an injected read-only port. It never reads a token, contacts GitHub, opens a journal, issues a grant or dispatches a request.

The selected event ID and digest bind a public opaque handle ID, public credential ID, App and installation IDs, one target repository and target digest, operation/request digest, run/attempt, issuer actor, reader identity, issue/observation time and expiry covering the proposed grant window. The reader claims only `read-public-token-binding` on the selected custody store and must differ from the effective-scope metadata reader and execution credential. The [#755 metadata result](provider-credential-metadata.md) now retains its validated reader IDs so this role separation can be checked across the join. Red-before callback tests found that mutation of a frozen metadata or native record during the event read could pass; the source now snapshots both and refuses drift. The result remains `authorized=false`, `can_dispatch=false`, `live_effects=0` and carries no token bytes.

These fake records do **not** prove that any token bytes correspond to the public credential ID or opaque handle. A protected owner must select an actual vault/backend and independently authenticate the event bytes, reader, issuer and handle-to-token mapping inside that backend. The public handle must be a nonsecret identifier; it must not be a token hash or token-derived value. Runtime token use must be bound to that verified handle only after the separate grant and durable CAS gates. The [negative controls](../../eng/tests/callable-isolated-v2-token-custody-identity/test_token_custody_identity.py) cover foreign/recomputed event fields, stale/duplicate/noncanonical records, broadened or shared reader scope, mutable input aliasing and zero local token/file/socket/SQLite access.

The closed archive and disabled workflows remain unchanged. [#550](https://github.com/FS-GG/FS.GG.Coordination/pull/550) native one-POST, [#545](https://github.com/FS-GG/FS.GG.Coordination/pull/545) disputed receipt, protected install/merge, Authority write and cutover remain held.

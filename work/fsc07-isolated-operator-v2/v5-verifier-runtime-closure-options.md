## Reviewable implementation choices

| Route | Interface and closure to review | Specific risk and control |
| --- | --- | --- |
| In-process, reviewed Ed25519 package | The [post-registry adapter](../../eng/callable_isolated_v2_v5_keyed_signature.py) already supplies exact public-key, payload and signature bytes to a fake port. Replace that port in a **new** runnable revision with a reviewed package and fixed verification API. Independently pin source/wheel and extracted-file hashes, transitive native extensions/shared libraries, CPython ABI, absolute load path, interpreter, standard library and runner image. Under `-I -S`, an external package needs an explicitly reviewed immutable import path. | A wheel name or local version string is not a byte pin. Native extensions cannot be assumed importable from the ZIP member. Refuse on changed package, extension, library, path, ABI or verifier result; load no package or execution token before no-grant refusal. |
| External OpenSSL CLI | A reviewed adapter could pass exact selected public-key, payload and signature bytes to an absolute, pinned `openssl pkeyutl` executable without a shell. Independently pin the binary, loader, linked libraries, provider modules/configuration, environment, temporary-file and subprocess custody, plus the runner image. | CLI success is not key approval. Refuse on binary/provider/configuration drift, wrong public-key encoding, altered bytes, nonzero or ambiguous exit, stray output and temporary-file leakage. The process and filesystem surface needs independent no-grant zero-access tests. |

No choice is made between these routes. No approved Ed25519 verifier interface has been identified on the observed `-I -S` Python import path. An unreviewed handwritten cryptographic implementation or direct `ctypes` call would introduce another implementation and ABI to qualify, not close the current evidence gap.

## Selection and acceptance boundary

The source owner can prepare a separate reviewable no-grant runnable revision only after the release owner chooses one verifier route and its exact dependency source/build/closure policy. Before protected installation, an independent reviewer must select the integrated Coordination commit/tree, new archive and manifest bytes, verifier implementation and dependencies, producer workflow/run/artifact, protected executor, runner image/interpreter closure and key-approval/revocation/nonce custodians. The selected protected runtime must independently reproduce its own closure; the local hashes above are examples of what to measure, not release pins.

Source tests for the chosen route must include an independently known valid Ed25519 vector, altered payload/signature/key, malformed key/signature, wrong algorithm, duplicate/noncanonical envelope, changed dependency bytes and broad/missing import or CLI path. Installed no-grant tests must prove zero execution-token read, nonce reservation, journal CAS, provider POST/PUT and cleanup before any verifier or authority dependency is loaded.

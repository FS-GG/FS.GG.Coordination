# Closed read-only workflow and run-actor adapter

Status: source and fake-transport controls, 2026-09-25, stacked on [#587](https://github.com/FS-GG/FS.GG.Coordination/pull/587). The [adapter](../../eng/callable_isolated_v2_workflow_read_adapter.py) implements only the workflow port of the [five-observer candidate contract](candidate-observer-port.md). It has no HTTP client, token lookup, protected credential, journal, grant, artifact installer or dispatch entry. The #563 inspect-only workflow remains disabled.

GitHub documents a [specific workflow run attempt read](https://docs.github.com/en/rest/actions/workflow-runs#get-a-workflow-run-attempt) requiring repository Actions read permission for a fine-grained token, and a [repository file content read](https://docs.github.com/en/rest/repos/contents#get-repository-content) requiring Contents read permission. The adapter's injected `ScopedReadTransport` may request only `GET repos/FS-GG/.github/actions/runs/{runId}/attempts/{attempt}` and `GET repos/FS-GG/.github/contents/.github/workflows/callable-isolated-v2-execute.yml?ref={workflowRevision}`. It never creates that transport. A future implementation must use fixed `https://api.github.com`, forbid redirects, select only the protected `.github` repository, and independently attest its App installation identity and effective `actions:read`, `contents:read`, `metadata:read` permissions without exposing a token. The source-level `scope()` dictionary is a claim, not that attestation.

The run response must name the exact numeric run ID/attempt, protected repository and head repository ID/name, `workflow_dispatch`, `main`, selected head SHA, exact workflow path, workflow ID and API URLs, and the same actor and triggering actor. A different rerun actor refuses. The file response must be a base64-encoded file at the selected commit, with the exact path, size, Git blob SHA and URLs. The adapter decodes and rehashes the bytes against the candidate's workflow SHA-256. It reads scope both before and after those two GETs and refuses drift, broad permissions, foreign repository, expiry, 3xx/4xx/5xx, duplicate JSON fields, malformed bytes and secret-bearing transport exceptions. Its output is an observation envelope and workflow bytes for #587; it grants no execution authority.

The [independent fake controls](../../eng/tests/callable-isolated-v2-workflow-read/test_workflow_read_adapter.py) cover wrong source/head, actor, run attempt, repository, path, content and blob digest; foreign or broad claimed scope, credential drift, redirect, duplicate JSON and sanitized exception. The positive control patches file, token environment, socket and SQLite access to fail. No protected run or file was fetched, no credential was installed and no live workflow was dispatched.

The next protected source decision is a separately reviewed read-only App transport and identity observer bound to an actual protected run, installation and repository selection. Its credential custody must be independent of the eventual selected-target execution token. An exact source/release observer, independent approval/membership observer, target/App-scope reader and sealed operation-plan reader are also missing. These read-only facts can only qualify a candidate after independent review; a native one-POST window still needs an installed effect artifact, selected target, durable CAS, one-use grant, no-grant refusal and complete native readback. The typed ceiling, gate/index, #545 receipt and cutover remain held.

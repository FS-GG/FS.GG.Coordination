# Independent reviewer and release approval witness

Status: source-only, non-authorizing fake-port contract. The [release preflight](effect-release-preflight.md) checks a claimed reviewer actor and manifest approval event, while the [producer witness](effect-producer-artifact-witness.md) checks the selected run and bundle. `eng/callable_isolated_v2_effect_approval_identity.py` joins those closed results to two separately scoped read-only observations.

The reviewer identity reader must attest the selected actor's active `FS-GG` release-reviewer role, login and identity record at a fresh time after artifact creation. A separate approval-event reader must return canonical immutable version 2 JSON bytes whose independently selected SHA-256, event ID, reviewer, manifest, selected source record ID, source revision/tree, producer run/attempt/actor, artifact/bundle and workflow hash/blob all agree. The reviewer join independently compares the producer witness's checked repository ID, actor and source record ID against its own selected repository and preflight before reading that event. The approval must follow the identity observation and remain unexpired. Reader principals and credentials must differ; both scopes are snapshotted and checked again after reading. The version 4 closed result retains the repository ID, actor and source record ID and remains `authorized=false`, `can_dispatch=false`, `live_effects=0`.

The [fake controls](../../eng/tests/callable-isolated-v2-effect-approval-identity/test_effect_approval_identity.py) first failed because the module did not exist. A red-before control showed that coherently changing reviewer-side repository IDs could reuse an unchanged producer witness; the repository join now refuses it. Earlier red-before controls showed that changing preflight's producer actor or source record ID and coherently rewriting the event could pass, that the immutable event could omit a selected source record ID, that reusing one mutable scope hid credential drift, and that a constructed producer result and coherently rewritten event could agree on a foreign workflow SHA-256 or blob ID. The reviewer join requires exact workflow pins and snapshots both scopes. Other negatives include inactive or self review, foreign reviewer/login, wrong source/run/artifact/manifest/workflow, duplicate event JSON fields, stale approval, changed digest and shared/broad/drifting reader scope. The matching fake denies file, environment-token, socket and SQLite access during qualification.

These injected claims do not authenticate a real reviewer, prove historical organization membership at approval time, or establish an immutable external event store. A protected release owner must supply and independently approve the exact event digest, authenticate distinct reviewer and event-reader principals, and verify the event's durable source and time. A disabled [producer workflow candidate](effect-producer-workflow-candidate.md) now exists in this stacked draft, but no protected integrated source, producer run or installation has been observed. Both proposed workflows remain disabled; #545 disputed receipt, the [#550 native one-attempt gate](https://github.com/FS-GG/FS.GG.Coordination/pull/550), typed gate/index, Authority and cutover remain held. No credential, grant, journal/CAS or provider POST is authorized.

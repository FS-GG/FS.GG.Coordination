# Closed v5 provider request specification

Status: source-only request-envelope proposal, stacked on [#749](https://github.com/FS-GG/FS.GG.Coordination/pull/749). The [pure source](../../eng/callable_isolated_v2_provider_request_spec.py) consumes the closed [native request custody join](native-request-custody.md), the same verified plan request bytes and typed v5 coordinates. It has no HTTP client, token lookup, journal writer, grant parser or dispatch function, and it is outside the installed archive.

The source requires the literal origin `https://api.github.com` and exact `POST repos/{selected repository}/pulls` path. Its frozen output carries the verified canonical body bytes with `max_sends=1`, `automatic_retries=0`, `follow_redirects=false`, `authorized=false`, `can_dispatch=false` and `live_effects=0`. Wrong scheme, host case, port, userinfo, query, fragment, trailing slash, foreign path, changed body, changed operation or request digest and changed write ceiling refuse. The [negative tests](../../eng/tests/callable-isolated-v2-provider-request-spec/test_provider_request_spec.py) first failed because the module was absent; they also assert no local token, file, socket or SQLite access.

This source specification does not enforce TLS peer identity, proxy exclusion or runtime retry behavior. A separately reviewed runnable artifact and installed provider adapter must implement those controls, use only the independently selected execution App token, count one actual send after authenticated grant and durable CAS readback, and perform complete native result readback after a response or loss. A prepared envelope is never evidence that a POST happened or that one is authorized. The closed archive, disabled workflows, [#550](https://github.com/FS-GG/FS.GG.Coordination/pull/550) native-effect gate and [#545](https://github.com/FS-GG/FS.GG.Coordination/pull/545) receipt dispute remain unchanged; no protected install, CAS, grant, provider request, merge, Authority write or cutover follows.

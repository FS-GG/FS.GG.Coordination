# Closed selected-target and App-scope read adapter

Status: source and fake transport only, 2026-09-25, stacked on [#591](https://github.com/FS-GG/FS.GG.Coordination/pull/591). The [adapter](../../eng/callable_isolated_v2_target_scope_read_adapter.py) implements the selected-target observer port of the [candidate contract](candidate-observer-port.md). It has no HTTP client, token lookup or mint, journal, grant or dispatch entry. The #563 inspect-only workflow remains disabled.

The four injected read paths are GET /repos/{selected}, GET /installation/repositories?per_page=100, and the selected source and base GET /repos/{selected}/git/ref/{ref}. GitHub documents the [repository object](https://docs.github.com/en/rest/repos/repos#get-a-repository), [installation repository list](https://docs.github.com/en/rest/apps/installations#list-repositories-accessible-to-the-app-installation) and [Git reference object](https://docs.github.com/en/rest/git/refs#get-a-reference). The reference read requires Contents read permission, so the selected read role claims only metadata:read and contents:read. The reader requires numeric and node repository identity, exact API URLs, one complete accessible repository with no pagination, and exact source/base commit SHAs. It refuses redirects, non-200 responses, malformed or duplicate JSON, foreign or extra repositories, moved refs and a read-scope change. A red-before control showed that reusing one mutable read-scope dictionary and changing its credential at the final read hid drift; the adapter now snapshots each validated scope. Its local scope result is a claim, not authenticated App or token provenance.

The adapter hashes each of the four exact response bodies and the canonical selected target. A separate injected protected attestor must bind those five hashes to an independent complete prestate digest and execution credential metadata: one installation ID, exactly one repository ID, only metadata:read, contents:read, pull_requests:write, and an unexpired issue window. No attestor is supplied here. The adapter cannot derive the complete PR/protection/prestate census or effective execution-token permissions from these four GETs; a future protected attestor must fetch and verify that census and the actual token issue record independently. The result is only a #587 target observation; composition remains authorized=false and can_dispatch=false.

The [fake negative controls](../../eng/tests/callable-isolated-v2-target-scope-read/test_target_scope_read_adapter.py) invert repository ID/node/URL, list completeness, ref identity and SHA, read scope, attestation digest, execution repository set/permissions/expiry, redirect, scope drift and exception sanitization. The matching control patches file, token environment, socket and SQLite access closed. These tests establish local refusal logic, not protected provider custody.

The next protected access decision must name the selected disposable target, exact repository ID/node, selected App installation and read principal, immutable attestation principal/source and complete prestate census. The read transport must fix https://api.github.com, forbid redirects and attest its identity and effective scope independently of its scope claim. The separate execution credential remains absent. The independent review event ID/time from #591, effect artifact/workflow, durable CAS, one-use grant and native one-POST readback are also absent. No result from this adapter clears #550, the typed ceiling, gate/index, #545 receipt or cutover.

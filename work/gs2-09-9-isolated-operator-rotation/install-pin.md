It does not change the #555 archive builder, #559 authority port, a protected workflow, a credential, a journal, or a provider. The GS2-09.9 typed ceiling, gate/index and receipt remain held.

## Exact candidate checked

The read-only verifier fixes the #555 zipapp name and SHA-256 `003f63ac1b0f895642a7000954607b0980f8e9f1dbb058576e66b40ed79cbfb7` (14,491 bytes), manifest SHA-256 `9cf485b238a458c3234adafb6f3964b7e105507a8d8cfbeb01a1d067b2545fd3`, builder SHA-256 `2c581bed909f835ae24de9b79ab1e2a1d4b144dd5dcf3b8b3285872c4af6ed6b`, and both source/member hashes and lengths. It also checks the #559 authority source hash `9a806bb78de25be887db0a0b9499f242d7989d33860e598e23e2ceff80172a26` while requiring that module to be **absent** from the installed archive. The archive must have only `__main__.py` and `callable_isolated_v2_grant.py` in fixed order, with the committed stored ZIP metadata. The install directory must contain only that archive, with canonical regular paths and no symlinks.

The interpreter descriptor requires a canonical absolute executable path, exact SHA-256, CPython patch version, and `-I -S` flags. The verifier hashes the binary before executing it, checks isolated/no-site runtime flags and the reported executable/version, then runs the exact archive from a fresh empty working directory with a sanitized environment. `--help` must yield the fixed inspect usage; `execute-native-pull` must refuse. Its evidence always returns `authorized:false`, `can_dispatch:false`, `live_effects:0`. The #555 manifest's entry hint names `-I`; this verifier proposes the stricter `-I -S` protected invocation. A future protected release packet must explicitly select that invocation and prove its compatibility with the reviewed artifact.

Local tests use the current machine's resolved Python binary as a **synthetic local pin**, not a protected interpreter selection. They reject archive hash drift, wrong/extra ZIP members including an authority module, changed source or manifest, extra install files, wrong interpreter hash/version/flags, and symlinked interpreter path. A sentinel token and journal path are excluded from all child process environments; the journal sentinel remains unchanged. The inherited #555 tests separately cover no token read, local HTTP canary request, or journal write through the zipapp. These checks do not constitute a protected workflow installation or a live provider/credential test.

## Protected release and approval still required

A protected release owner must choose an immutable Coordination revision containing the reviewed source, publish and independently read back the exact archive and manifest, and pin a `.github` workflow revision/path/hash, runner or container image digest, interpreter binary path/hash/version, runtime libraries and standard library image, and the `-I -S` command. The interpreter descriptor must be sealed by that protected workflow/release decision; accepting a caller-computed hash and version as its own authority would prove only self-consistency. The installed workflow must run the clean-install negative controls against those exact bytes with no execution credential present. Any changed source or artifact requires a new pin and review.

This archive intentionally has no trusted authority or journal adapter and cannot execute a POST. A later, separately reviewed effect artifact must attach the #559 port to independently scoped protected authority, issuer, replay, target, journal and execution roles, prove exact selected target and atomic one-attempt behavior across restart, then obtain complete native readback. The [one-operation amendment](authority-amendment.md) still requires a distinct reviewer to approve the exact protected run/attempt and a one-use grant before the native effect. No such reviewer, target, workflow, interpreter release pin or CAS backend has been selected here.

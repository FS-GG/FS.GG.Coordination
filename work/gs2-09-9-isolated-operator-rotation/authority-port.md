# Isolated v2 authority and journal port candidate

Status: source and local tests only, 2026-09-25. This draft stacks on the inspect-only zipapp in #555. It adds `eng/callable_isolated_v2_authority.py` and a synthetic negative corpus; it does not change that zipapp, install a command, issue a grant, obtain a token, call GitHub, write a journal, or dispatch a provider effect. The current GS2-09.9 typed permission ceiling, gate/index and receipt remain held.

## Boundary and custody

The candidate defines three **separate future read ports**. `ProtectedAuthorityObserver.observe_current` must derive the exact current protected run, reviewer approval and membership, source, selected target and prestate, credential metadata, operation, and committed journal intent. `ProtectedGrantIssuer.read_issuance` must independently read the one-use issuance event and single-member artifact envelope. `ProtectedReplayObserver.read_replay` must independently reread the same grant ID and operation ID at the protected journal. The issuer port declares `issue_once`, but no source calls it and no implementation exists. Passing a locally supplied object through these protocols does not establish its provenance. A protected implementation must bind each port to its own scoped credential and readback, forbid an actor from supplying their own approval, and verify the issuer's authority separately.

`plan_issue_request` validates the full observed grant bindings with the #554 parser's shape rules, then hashes a canonical candidate request. It does not allocate a nonce or grant ID and returns `authorized:false`, `can_dispatch:false`, `live_effects:0`. The issuance readback must bind that request digest, run ID/attempt, approval ID, distinct issuer actor, issuance event, grant ID/nonce, UTC issue time, artifact archive hash, and payload hash. The verified artifact must contain exactly one stored `grant.json` member with the expected payload digest. The #554 parser then compares those bytes with the independently observed complete fields and a fresh unused replay observation. Its result and this module's result remain non-dispatchable.

The journal port declares `compare_and_swap` and `read_back` without an implementation or caller. `plan_attempt_reservation` derives one exact-parent `attempt-may-have-started` marker from the verified candidate: protected repository/ref, prior generation/head, next generation, grant and payload digest, operation and canonical request digest, run/attempt, and target/prestate. `verify_attempt_readback` requires an accepted CAS result and a separate complete reread of the same new generation/head and entire marker. A lost acknowledgement, moved parent, partial read, changed marker or conflicting head refuses. Even a matched synthetic readback returns `can_dispatch:false`; it does not create a one-use POST capability.

The local tests use fictional IDs and an unselected `.invalid` target. They cover missing and shared ports, incomplete authority, foreign source/target/credential/approval/issuance bindings, self-issuer, wrong issue digest, expired issue, changed archive/payload, duplicate member, used replay, CAS loss/conflict and foreign readback. The positive fixture remains closed while token environment lookup, socket creation, and file/journal opening are patched to fail. No protected run, source installation, App role, target, CAS backend, or real grant was tested.

## Next protected decision packet

Before an installed effect command or one-operation approval, the owner must select and record immutable Coordination and `.github` workflow revisions/digests; the exact installed zipapp/package entry and hash; a disposable target repository ID/node/installation, source/base refs and SHAs, complete prestate and policy; a protected run/attempt, independent reviewer, membership and approval event; separate scoped authority, issuer, replay, journal, target-read, and execution credentials with effective grants and expiry; and a qualified protected journal repository/ref/backend with exact CAS semantics and independent readback. The issuer must sign or durably seal one canonical artifact for that run and request digest; a standalone local object or #552 Q4 sandbox proof cannot satisfy this port.

The future executable must prove no-grant zero token read/POST/journal write, exact protected provenance through the installed entry, one durable marker before any POST, one POST at most across a lost response and fresh process, and complete native poststate readback. It must retain Unknown on uncertainty. Only after those protected source/setup qualifications can the distinct reviewer approve the exact execution run and the separate issuer create its one-use grant under the proposed [authority amendment](authority-amendment.md). That approval/issuance is the smallest protected authorization point. This draft is not a request to perform it.

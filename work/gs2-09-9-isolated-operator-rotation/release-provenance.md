# Proposed protected provenance packet for the inspect-only v2 archive

Status: source-only decision packet, 2026-09-25. This draft stacks on #561 and adds a pure packet validator with fictional negative controls. It does not create a workflow, select a runner, install an archive, read an execution token, issue a grant, or authorize an effect. GS2-09.9's typed ceiling, gate/index and receipt remain held.

## Existing workflow boundary

At protected Coordination `main` revision `b8225f6b63f764f58ec20735d3cf849b37c57276` (remote ref checked), `.github/workflows/callable-cli-release-prepare.yml` has SHA-256 `f5fa33ff6433a3c91cb0bb8c2ea7049edfb6a3ab7ca90e33a0dd2c948bbede7b`; `.github/workflows/callable-cli-release-publish.yml` has SHA-256 `8e2cccd1ef01cac4741bdbc0e59f649114f2aebe1e5d53cbb7d4abcc3634a69e`. Both use `ubuntu-latest`. The prepare workflow stages a .NET CLI candidate. The publish workflow pins historical `FS.GG.Coordination.Cli` 0.1.2 source/merge/package hashes and has `contents:write`, `packages:write`, `id-token:write`, `attestations:write` and artifact metadata write permission for external publication. Neither is an isolated-v2 zipapp release workflow, an immutable image pin or an approved protected inspect installation. There is no `.github/workflows/callable-isolated-v2-release.yml` on that protected revision. The current ordinary CLI publication evidence cannot be relabeled as #555–#561 installed provenance.

## Packet contract and unresolved selections

`eng/callable_isolated_v2_release_provenance.py` accepts at most 16 KiB of canonical JSON under `fsgg.coordination.callable-isolated-v2-release-packet/1`, with `state:prepared-not-authorized`. It rejects missing, extra, duplicate, foreign, broad or expired fields and returns `authorized:false`, `can_dispatch:false`, `live_effects:0`. A supplied packet digest must match, but its protected origin is still unproved until a separate release decision pins it. Two **distinct future read ports** must independently supply complete source/artifact/runner/run observations and the environment approval/membership observation. This branch supplies no implementation for either port; matching local dictionaries are test fixtures, not trust.

The protected release owner must first select and review the new workflow and immutable runner image, merge only approved source bytes, and independently pin the packet digest. A no-execution-token release job then downloads and rehashes the single archive, installs it into a clean read-only directory, regenerates the runtime closure, verifies the independently approved digest and runs the installed no-grant/unknown-command controls. An independent reader records the workflow/run/environment approval, artifact download and runner observations. Any missing selection, source drift, mutable runner, broad workflow permission, local closure reuse or uncertain readback refuses the release packet.

This is a release provenance gate for an **inspect-only** artifact. A later effect artifact still needs separate protected authority, issuer, target, journal CAS, execution credential, one-attempt recovery and complete native readback. The distinct reviewer approval and one-use grant in the [operation authority amendment](authority-amendment.md) remain the final protected authorization point for one POST. No release packet or source merge can substitute for that gate.

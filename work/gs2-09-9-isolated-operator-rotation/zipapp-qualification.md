# Inspect-only v2 zipapp source candidate

Status: local source and artifact qualification, 2026-09-25. This draft stacks on #554 and implements its [installed-entry decision](installed-no-grant-decision.md). It does not publish, install in a protected workflow, authorize or execute a provider operation. The current GS2-09.9 typed permission ceiling and gate/index/receipt remain unchanged.

`eng/build_callable_isolated_v2_zipapp.py` builds `fsgg-callable-isolated-v2.pyz` from exactly two source files: `eng/callable_isolated_v2_entry.py` as `__main__.py` and #554's `eng/callable_isolated_v2_grant.py`. ZIP member order, timestamp, permissions, storage method and comment are fixed. The [manifest](zipapp-manifest.json) records the builder, source/member and archive SHA-256 digests. Two independent local builds produced the same bytes. The local archive SHA-256 is `003f63ac1b0f895642a7000954607b0980f8e9f1dbb058576e66b40ed79cbfb7`; it is a candidate artifact, not a published or protected installation.

The only entry is `python3 -I /absolute/path/fsgg-callable-isolated-v2.pyz inspect-grant --grant FILE --digest SHA256 --expected FILE --replay FILE`. `--help` prints static usage. Missing or unknown actions, duplicate/missing arguments and malformed inputs return fixed refusals without echoing raw values. The entry reads only three bounded regular local input files for an inspection request. It never reads an environment variable, obtains a token, constructs an HTTP client, reads or writes a native journal, or exposes a POST command. Even a parsed synthetic grant returns `authorized:false`, `canDispatch:false`, `liveEffects:0` and `parsed-not-authorized`.

Local tests build two archives, compare their full bytes with the committed manifest, inspect each ZIP member and its source hash, copy the artifact into a clean temporary install directory, and run it with `python3 -I` from an empty working directory. Synthetic credential variables, a local HTTP canary and a native-journal sentinel remain unused. An in-process entry test rejects any environment lookup or foreign file open and asserts no socket connection. A synthetic grant parses through the archive without changing its input files, artifact or journal sentinel. These are three focused zipapp tests plus #554's six grant-parser test methods; the test inputs are fictional and no GitHub request occurs.

This proof is local. It does not establish protected workflow installation, a live provider or credential path, durable atomic replay prevention, or accepted native readback. A later protected source candidate must pin the archive and interpreter in a protected workflow, repeat these negative controls against the exact installed bytes, add separately verified grant/target/journal ports and one-attempt controls, then obtain the distinct one-operation authority described in #550. No environment approval or grant request follows from this archive.

# Review draft: one protected v2 isolated PR operation

Status: proposed owner amendment, 2026-09-25. This text is not an authorization, grant, installed workflow, or GS2-09.9 receipt. The [effect-adapter proposal](effect-adapter.md) identifies the missing executable ports. The current typed GS2-09.9 permission ceiling still excludes new provider mutation and external acceptance. The earlier V2-CALL-01.4b protected operation was a separate authority for a historical v1 subject; its target, reviewer, grants and receipts do not transfer to this v2 operation.

## Proposed narrow authority

The owner would authorize one new synthetic pull request on one newly admitted disposable repository, for one operation ID and one workflow run/attempt, after installing the exact reviewed v2 source and protected workflow. The only execution-provider write is one canonical `POST /repos/{owner}/{repo}/pulls`. This authority excludes a branch-protection PUT, merge, repository or branch creation, visibility/billing change, Project write, migration, production writer enablement, cleanup and GS2-09.9 acceptance. Setup, protected journal writes and cleanup each need their own bounded authority and receipt; they cannot be hidden inside the one POST count.

The protected authority packet must be a single canonical artifact with schema `fsgg.coordination.callable-isolated-v2-authority/1`, `state: prepared-not-authorized` until independent environment approval, and the following exact bindings. A field marked *unselected* prevents issuance; a dispatch input cannot supply it later as authority.

## Approval and stop sequence

1. A separate protected source change installs the v2 command, grant verifier, selected-repository GitHub transport and journal port. It proves the no-grant and one-attempt negative controls through the installed entry. A protected operation-authority amendment is reviewed against those immutable bytes. No source merge by itself approves the effect.
2. Separately authorized setup creates or selects the synthetic target and source/base branches, then seals complete prestate and capability evidence. A separately authorized journal writer commits and reads back durable intent. These steps finish before the execution environment's approval; the execution job cannot create its own evidence of independent approval.
3. The independent reviewer receives the complete source, target, credential, journal and operation packet and approves the exact execution run/attempt in the protected environment. An authorizer issues a one-use grant artifact bound to that approval, with a single canonical payload, archive digest and short expiry. This is the smallest nondelegable authorization point for the POST.
4. Immediately before dispatch, the installed operator independently re-reads the protected run, reviewer, artifact, App installation/token scope, target prestate and journal generation. Any missing or changed fact closes the gate with zero POST. After the attempt marker may have started, it never retries that POST; 2xx, lost response and 5xx all require complete native readback. Explicit 3xx/4xx returns Unknown.
5. Independent verification seals the native result before a new process proves no-repeat. A separate cleanup grant follows only after verified native evidence. Unknown or partial results retain the target and evidence for review; they do not receive automatic compensation or a GS2-09.9 receipt.

The smallest request once this packet is complete is approval by a distinct authorized reviewer of the exact protected execution run/attempt and issuance of its one-use grant. Today that request cannot be made: there is no installed v2 effect command, protected grant verifier/workflow, selected target, v2 CAS journal, or independent reviewer binding. This draft keeps those missing coordinates visible and cannot be dispatched.

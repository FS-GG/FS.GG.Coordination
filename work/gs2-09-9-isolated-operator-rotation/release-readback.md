# Proposed exact readback for a later inspect-only v2 installation

Status: source-only procedure and negative controls, 2026-09-25, stacked on draft #563. The #563 workflow is disabled with `if: ${{ false }}`; this draft neither enables it nor runs a protected installation. The [pure readback verifier](../../eng/callable_isolated_v2_release_readback.py) accepts synthetic observations for contract tests and always returns `authorized:false`, `can_dispatch:false`, `live_effects:0`. It has no observer implementation, credential, workflow API, journal or provider port. Matching caller-supplied data is not protected provenance.

## Protected selection and sealing

A distinct protected release reviewer must first approve the source, workflow, #555 artifact and immutable runner/image choices for a later **inspect-only** run. After that run and its independent readbacks, the reviewer can seal a canonical `fsgg.coordination.callable-isolated-v2-release-selection/1` document within the approval window. Its exact fields are enforced by the verifier: protected Coordination source commit and tree, workflow SHA-256, #555 archive and manifest SHA-256, OCI runner image by digest and image attestation SHA-256, interpreter/closure/standard-library tree SHA-256, packet SHA-256, run ID/attempt, environment ID, approval ID and reviewer ID. The selection has `state:selected-not-authorized`. The selection digest must come from that protected review record; a digest supplied by the same candidate has no authority. Run and approval IDs and the protected closure digest are read back before this final seal, rather than guessed before the run.

The protected source commit must contain reviewed #555–#563 bytes, subsequent reviewed repairs and the readback verifier itself. It cannot be #563's draft head `55ca33b7b45fd81889ffbccb4fbd4939f352b7d3` or an all-zero placeholder. The selected workflow must be a separately reviewed **new runnable revision**, not the current disabled template SHA-256 `c486fe746ee88536897c277fc1cbcc320813c08d4b876dacb01adb78da759e93` or #563's earlier disabled digest `1aac83c07ad0c798bd946dfecc87d16924a94455c05b566d43b44eb70aa445b9`. A protected owner must separately review any change that makes the job runnable. This source draft supplies no selected protected commit, image, attestation, packet or runtime digest.

The archive and manifest remain the exact #555 candidate: `003f63ac1b0f895642a7000954607b0980f8e9f1dbb058576e66b40ed79cbfb7` and `9cf485b238a458c3234adafb6f3964b7e105507a8d8cfbeb01a1d067b2545fd3`. The runner must be an attested ephemeral Linux amd64 host with a read-only root and an OCI image reference ending in `@sha256:<64 lowercase hex>`. A mutable tag, `ubuntu-latest`, the unselected #563 image, a zero digest, or #561's local closure `6783d094396af466461f3dfc8e8d0e41dada34b177e1c06dd784806c79979162` refuses. The protected reviewer must independently select the new closure after installed readback; these values cannot be inferred from local tests.

## Four distinct protected readbacks

1. **Release observation:** read the protected `main` commit/tree and exact workflow bytes at that revision. Independently hash the #555 archive downloaded from the selected producer run and artifact ID, read the manifest, image digest and attestation, interpreter bytes and version under `python3 -I -S`, closure manifest and standard-library tree. Read back the actual run ID/attempt, environment ID, actor, ref, event and read-only permission set. The [packet contract](release-provenance.md) requires every source, workflow, artifact, runner, runtime and run member to match this observation exactly; missing or foreign fields refuse.
2. **Approval observation:** independently read the protected environment approval event, active reviewer membership, reviewer ID, approval ID, run ID/attempt, environment ID and bounded approval time. The reviewer must differ from the run actor. A named environment or a submitted approval value alone is insufficient. No execution App token, journal credential, selected-target credential or cleanup token may be present in this inspect-only job.
3. **Installed control observation:** after a separately reviewed release workflow has installed the exact archive in an otherwise empty read-only directory, retain the canonical absolute `installedArchivePath` and full argument vectors, exit codes and SHA-256 of stdout/stderr for `<packet interpreterPath> -I -S <installedArchivePath> inspect-grant` and `<packet interpreterPath> -I -S <installedArchivePath> execute-native-pull`. The interpreter path must be the one independently read back with the packet's pinned interpreter hash; both commands must use the same installed archive path, whose basename is the #555 archive name. The first must exit 2, emit empty stdout and `inspect-refused:inspect-arguments\n` on stderr; the second must exit 2, emit empty stdout and `inspect-only\n` on stderr. Read back the archive, interpreter and closure hashes **after** both probes and record the completion time as `observedAt`. Attest that the execution token was absent and that provider requests, journal writes and working-directory writes were zero. The controls record is complete only when its source revision/tree, actor ID, producer run/artifact IDs, release run/attempt and hashes all match the selected values. Its observation time must be within the approval window and no later than verification time.
4. **Selection-review observation:** from a distinct protected read-only role, read a complete review event strictly after the installed-control observation and before approval expiry. The event must name its own repository, workflow path, source revision, run ID/attempt, environment ID, dispatch actor ID and approval ID; these fields must match the independently observed packet and selected values. It must bind the exact canonical selection bytes and digest, including source/tree, packet, producer run/artifact IDs, runner image and attestation, installed closure, run/attempt, actor and distinct active reviewer. The review event ID is separate from the environment approval ID. A candidate-supplied digest or matching packet dictionaries cannot supply this event.

The release, approval, control and selection-review observers must be separate protected read-only roles, with their custody and retained evidence reviewed independently. The source `Protocol` objects and fictional unit-test dictionaries establish only interface consistency. Any unavailable observer, incomplete readback, changed post-probe hash, successful command, wrong stderr, token presence or nonzero effect/write count refuses the packet. A failed or uncertain readback stops; it is not retried as a native operation.

`verify_selected_readback` first checks the exact selection digest and shape, then calls #562's packet validator with distinct release and approval observers, compares every selected pin and event ID to the validated packet, checks the installed refusal controls, and requires a fourth selection-review observation. Negative source tests cover wrong draft head, held workflow hash, mutable runner, absent or same-actor reviewer, wrong packet/pin, missing fields, incomplete controls, wrong interpreter/flags/archive arguments, effect counters, event-origin mismatch and a review before the controls completed. The test pins are fictional; none is an approved release.

This procedure qualifies only a future inspect-only installation. It does not change the GS2-09.9 typed ceiling, issue a one-use grant or authorize a native POST. Selected target, actor and credential custody, protected journal CAS, one-attempt recovery, complete native readback and separate operation reviewer approval remain the later [authority gate](authority-amendment.md). Gate/index and receipt remain held.

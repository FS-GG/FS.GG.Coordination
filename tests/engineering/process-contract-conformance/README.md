# Process contract conformance caller

This non-packable net10 test-only executable calls the actual portable Contracts
budget, lifecycle and bounded sink using real fixture byte, exit and EOF events.
It is the selected .2-C conformance bridge; no production runner, new package,
consumer migration or containment implementation is selected.

The frozen matrix has eight cases in six categories: literal argv/environment with
normal binary output; missing executable and pre-start cancellation; dual flood;
a finite failed consumer sink; leader exit with an inherited writer; original work
deadline and caller cancellation. Cases run serially. A semantic failure remains
original and can coexist with later independent cases only after positive local
release. Refused observations or unresolved local custody stop the remaining cases.

`FixtureSession` is retained before launch. Its one original operation budget is
three seconds: 500ms work plus 2500ms cleanup reserve. Run returns the latest report
at work/cancellation/failure; pending readers and original authority remain with the
same lease. Actual byte appends and lifecycle snapshots are serialized as one
observation, while stdout/stderr reads remain independent. The failed sink performs
one real write to a disposed MemoryStream outside the bounded core sink. Stdout
charges but retains zero; stderr is independently drained. No arbitrary callback enters
the core sink. Local release needs settled tasks and positively observed leader
termination; whole-workload empty/reaping remain Unknown and public cleanup remains
Incomplete. Process disposal alone cannot qualify it.

No fixture can start without the exact one-use descriptor/digest, literal HOME,
Linux profile, current direct independent owner birth, accepted owner profile,
fixture/interpreter hashes and loaded caller/Contracts assembly hashes. The selected
source manifest's SHA256 is the operation source digest; its Git revision stays a
separate field, and all 68 source inputs must still match before any lease is made. An inherited
writer additionally requires explicit qualified inherited-writer support. The owner
profile must actually retain its demonstrated scope across caller failure/exit;
booleans or evidence strings are not native authority. The independent outer owner
must be separately reviewed and admitted. Reusing the failed heldpipe acquisition or
relaxing the no-descendants bootstrap is excluded. If that route is unavailable,
prepare the existing supported disposable/hosted route and leave affected acceptance
pending. The caller sends no signals and never creates a background reaper.

Build/restore and native execution need separate root grants with pinned source,
SDK/cache/runtime, original clocks, combined resources, receipts and custody. The
private preparation packet supplies exact proposed commands and descriptor shape.
The expected lock has only FSharp.Core 10.1.302 and the existing Contracts project
edge; it is source-prepared and must be validated by actual locked restore. No new
restore, build or fixture execution occurred during source preparation.

The entry accepts descriptor path and SHA256. It writes a bounded plain DTO report
and keeps original execution failures separate from publication failures. Original
case snapshots remain independent from subsequent local cleanup observations. A
passing case never upgrades external sampled custody to containment or a complete
workload. .2 completion still requires actual selected disposable fixture evidence;
.3 backend and consumer adoption are outside this caller.


Mutable cleanup and release bundles are constructed from current local observations
under one lease gate, with one captured event tick for all proof fields. Positive
old mutable evidence is not reused. A fresh original-work/cancellation check guards
both actual helper launch and stdin G release. G also requires the retained Process
to observe the original live birth; denial closes stdin and retains started tasks
and handles for original cleanup. Helper launch, the G gate and G completion are
recorded separately. The finite gate is not an ownership mechanism.

Receipts expose original domain/frequency/start/work/total expiry, Run snapshot and
caller observation ticks, later cleanup/release ticks, work-stop timing and the
original observed leader PID/birth/scope. Acceptance refuses observations outside
the original total window; actual work overrun remains visible, without claiming
hard managed scheduling. Held-writer/deadline/cancel probe TryRelease before waiting
for cleanup and require actual pending obligations plus refusal at that decision.
A legitimate settled race is safe but leaves pending-refusal coverage unobserved.

Twelve finite preflight controls use the actual cleanup-bundle constructor/reducer
with advancing synthetic ticks and the actual original-budget release predicate.
They check stale versus fresh settled/released/no-effect bundles and current,
elapsed, cancelled or invalid-clock startup decisions. Synthetic reducer generations
are control data, not native birth or ownership evidence. These controls are source
prepared and unexecuted here; they do not rerun or alter the 69 accepted controls.

## Additive producer retirement preparation

The production fixture now accepts an explicit retirement policy through
`ProductionFixture.prepareWithRetirement`; the existing `prepare` route keeps
DirectChild and its original seven-case behavior. Public portable Contracts and
the test-only .2 bridge remain unchanged. The tree policy is best effort only and
retains the same process/stop task through its original budget.

A direct-child negative control must record the observed live descendant and
pending local readers before the independently admitted outer stage retires its
owned scope. It cannot claim local release or complete tree custody to make a
passing receipt. The existing stage guard/profile adaptation is still preparation;
no negative execution or new owner route is accepted by these source changes.
The unchanged 30-second descendant/200ms workload body is also exercised by the
additive FsQuint caller-owned API in its separate candidate receiver tests.
